# Windows basic native sandbox

`windows` (and `native` on Windows) uses a Low integrity, write-restricted token. Workspace-specific and per-command scratch SIDs grant writes. Ambient Low integrity paths writable by Everyone or the logon SID remain writable. Reads and network are unrestricted; strict process read-only and denied-network requests fail before execution. This is a partial write boundary.

The launcher starts the command suspended, assigns it to an unnamed Job Object with kill-on-close and no breakaway, then resumes it. On ordinary command exit it terminates remaining descendants and waits for the job's active process count to reach zero before returning. Killing the launcher closes the job handle and terminates its descendants. The provider marks the plan's process tree as contained.

The ACL helper is captured into Host memory when the backend module loads, then transported as compressed data to a constant PowerShell bootstrap. Guest edits to a workspace copy of `acl.ps1` cannot become host cleanup code. Before loading a cached launcher or using journal state, the Host refuses reparse points, hardlinks, and Low integrity objects in those control trees, and verifies Medium or higher integrity on their ancestors. It does not automatically change ACLs on a potentially unsafe existing cache. Volume roots and canonical workspace roots containing the current launcher cache or fixed journal state are refused before workspace ACL changes.

Workspace grants preserve original DACLs and mandatory labels in a flushed journal. The helper pins filesystem handles without delete sharing during grant/restore, rejects reparse points and hardlinks, and refuses more than 100,000 objects. Reparse/hardlink trees therefore need an explicitly selected environment that can support them safely. Each in-process workspace lease is reference counted. Overlapping in-process workspace roots are refused. A second Host cannot hold any concurrent workspace ACL lease for the same user; this conservative rule also prevents parent/child roots from receiving overlapping grants. The cross-Host lock and journals use the account-derived profile at `.yuantu/sandbox-state/windows`, independent of TEMP and USERPROFILE overrides and MSIX AppData virtualization.

The workspace root's `.git`, `.yuantu`, `.agents`, `.codex`, `.aws`, `.ssh`, and `.gnupg` paths are reserved and protected. Existing directories with these names deeper in the tree are also protected, but arbitrary future nested names are not a promised boundary. The Host trusts configuration at the workspace root. An absent root path is temporarily represented by a protected empty directory, so commands such as `git init` cannot create trusted metadata while confined. Successful cleanup removes only empty reservations created by that lease, and keeps any operator-created content. A failure before the journal exists rolls back owned empty reservations. A crash or partial security mutation retains journals/locks for manual reconciliation; it never guesses that a process is dead or silently overwrites changed ACLs.

After the final workspace lease ends, existing objects recover their original security and newly created objects receive Medium integrity labels. Approved atomic file replacements can inherit the same effective Low mandatory label: recovery ignores only the mandatory-label ACE's inherited provenance bit when checking for conflicts. DACLs, label SIDs/policies, and all other inheritance flags must still match; genuine operator permission or integrity-level changes retain the journal and lock without partially restoring other objects. Cleanup of a forged or deserialized plan cannot release a Host-owned lease or delete an arbitrary path. The owning Host must terminate the process tree before cleaning its original plan.

The administrator-initialized backend remains [implementation pending](ENHANCED-DESIGN.md). No account or firewall initialization is implemented or performed by the basic backend.
