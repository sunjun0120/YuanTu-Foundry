# Windows native sandboxes

`native` always selects `windows-account` on Windows and fails closed until its dedicated accounts are initialized and verified. Shipped apps migrate legacy `windows` command and hook settings to `native`; isolated presets also select `native`. The retired token provider is gone; historical ACL journals still recover with `sandbox-recover`. Settings > General > **Windows sandbox accounts** reports status and offers administrator setup, repair and uninstall. Setup refreshes the live Host without changing a session's permission preset. Development builds offer the same setup: it requests UAC only when the current process is not already elevated.

The account backend ships as `yuantu-sandbox.exe`: a desktop-user broker starts an offline or online account runner, which creates commands inside kill-on-close Jobs. Standing workspace grants use the sandbox group and a per-workspace capability SID; read-only commands omit the capability. WFP filters deny the offline account network access. Credentials use CurrentUser DPAPI. The runner replaces profile, HOME, identity and scratch variables and strips desktop-user cache/config overrides. Setup runs in the calling process when it is already elevated; otherwise it raises UAC for the fixed `account-initialize` / `account-remove` operations.

Setup grants group RX to safe PATH directories under the desktop user's real profile and `.gitconfig`. Settings can add or revoke an absolute read-only path. Sensitive directories and their ancestors, reparse points, hardlinks and trees larger than 100,000 objects are refused; unsafe default PATH entries remain inaccessible. Read grants are non-inheritable snapshots: newly installed tool files need reauthorization, and newly created secret directories receive no grant. `read-grants.json` records original DACLs and filesystem identities before mutation. Removal reopens recorded file IDs even after same-volume moves, revokes owned RX and preserves other trustees' changes. Identity or permission conflicts retain the recovery record. Read and workspace grants are revoked as the desktop user before fixed UAC account removal, even when UAC uses another administrator.

For workspaces and toolchains under the desktop profile, ancestor directories receive only non-inheritable traverse and read-attributes rights. Node's path resolution can inspect those ancestors without listing them or reading files elsewhere in the profile. These separate grants are recorded in `traverse-grants.json` and revoked after workspace/read grants during uninstall.

Real accounts are verified only on disposable GitHub Actions Windows runners in [the account workflow](../../../.github/workflows/windows-account-sandbox.yml). Local unit/development-runner tests never provision accounts. Packaging no longer verifies an Authenticode signature or requires a protected installation directory: the helper is trusted by its fixed location beside the application, and a missing helper is an error. The official Node runtime is still checked against the release key's signed checksums. Commands use private desktops and terminal plans use ConPTY; their real-account journeys remain CI-only.

## Removed basic backend

`windows` used a Low integrity, write-restricted token and was only a partial write boundary: reads and the network were unrestricted, and child processes hit `spawn EPERM`. It has been removed. Old `windows` command and hook settings migrate to `native`; executing the retired mode fails closed with a message naming `native` and `host`. No shipped code starts a token launcher, and there is no fallback to it.

Historical workspace grants still recover. `yuantu-agent sandbox-recover` restores the journals that launcher left behind and keeps journal and lock when a recorded DACL, label SID/policy or other inheritance flag genuinely changed.

The ACL helper is captured into Host memory when the recovery module loads, then transported as compressed data to a constant PowerShell bootstrap. Guest edits to a workspace copy of `acl.ps1` cannot become host cleanup code. Before using journal state, the Host refuses reparse points, hardlinks, and Low integrity objects in those control trees, and verifies Medium or higher integrity on their ancestors. It does not automatically change ACLs on a potentially unsafe existing cache. Volume roots and canonical workspace roots containing fixed journal state are refused before any workspace ACL change.

Workspace grants preserve original DACLs and mandatory labels in a flushed journal. The helper pins filesystem handles without delete sharing during grant/restore, rejects reparse points and hardlinks, and refuses more than 100,000 objects. Reparse/hardlink trees therefore need an explicitly selected environment that can support them safely. Each in-process workspace lease is reference counted. Overlapping in-process workspace roots are refused. A second Host cannot hold any concurrent workspace ACL lease for the same user; this conservative rule also prevents parent/child roots from receiving overlapping grants. The cross-Host lock and journals use the account-derived profile at `.yuantu/sandbox-state/windows`, independent of TEMP and USERPROFILE overrides and MSIX AppData virtualization.

The workspace root's `.git`, `.yuantu`, `.agents`, `.codex`, `.aws`, `.ssh`, and `.gnupg` paths are reserved and protected. Existing directories with these names deeper in the tree are also protected, but arbitrary future nested names are not a promised boundary. The Host trusts configuration at the workspace root. An absent root path is temporarily represented by a protected empty directory, so commands such as `git init` cannot create trusted metadata while confined. Successful cleanup removes only empty reservations created by that lease, and keeps any operator-created content. A failure before the journal exists rolls back owned empty reservations. A crash or partial security mutation retains journals/locks for manual reconciliation; it never guesses that a process is dead or silently overwrites changed ACLs. A refused command names the state it found — another live Host holds the lease, a dead owner left only locks, a dead owner also left journals to restore, or a lock names no owner — and that check runs before a command is offered for approval, so a lease nobody can get past costs no approval. `yuantu-agent sandbox-recover --dry-run` reports the same state; without `--dry-run` it restores every journal and only then removes the locks, refusing while any owner is alive or unidentifiable and keeping journal and locks when a restore fails.

After the final workspace lease ends, existing objects recover their original security and newly created objects receive Medium integrity labels. Approved atomic file replacements can inherit the same effective Low mandatory label: recovery ignores only the mandatory-label ACE's inherited provenance bit when checking for conflicts. DACLs, label SIDs/policies, and all other inheritance flags must still match; genuine operator permission or integrity-level changes retain the journal and lock without partially restoring other objects. Cleanup of a forged or deserialized plan cannot release a Host-owned lease or delete an arbitrary path. The owning Host must terminate the process tree before cleaning its original plan.

The earlier SYSTEM-service design is retained as [historical reference](ENHANCED-DESIGN.md). The account backend does not initialize firewall policy for the removed token backend.

## 本机开发测试

本机只做构建和只读检查；真实建户/删户只在一次性 GitHub Actions Windows runner 上做（见 `.github/workflows/windows-account-sandbox.yml`）。不要在本机执行账户初始化或卸载，除非你明确要在这台机器上使用账户沙箱。

1. 构建 helper：`npm run build:windows-sandbox`。它同时写入 `packages/tools/windows-sandbox/yuantu-sandbox.exe` 和 `dist/packages/tools/windows-sandbox/yuantu-sandbox.exe`；安装包和 `npm run build` 都从这里取。
2. 启动开发版桌面：`npm run desktop`（会先构建）。打开设置 → 通用 → **Windows 沙箱账户**，点“管理员初始化”。未提权时会弹一次 UAC；从已经提权的终端启动时直接在本进程执行，不再弹 UAC。开发版和正式版走同一套流程。
3. 初始化成功后，系统里会多出：
   - 本地账户 `YuanTuSandboxOffline`、`YuanTuSandboxOnline`，以及本地组 `YuanTuSandboxUsers`；
   - 两个账户的交互登录权限、远程/网络登录拒绝，以及登录界面隐藏项；
   - 离线账户的 WFP 过滤器（按该账户 SID 断网），必要时把 Secondary Logon 服务设为手动启动；
   - `%USERPROFILE%\.yuantu\sandbox-state\windows-account\setup_marker.json`（版本、账户/组 SID、离线过滤配置）和 `credentials.json`（DPAPI 加密的密码）；
   - 工作区授权、默认只读白名单，以及桌面 profile 下祖先目录的 traverse/read-attributes 授权记录。
4. 卸载：在同一设置页点“卸载沙箱账户”。它会先删除 `setup_marker.json`，再以桌面用户身份撤销工作区/读取授权，最后删除账户、组、WFP 过滤器和凭据。确认已清理干净：
   - `packages/tools/windows-sandbox/yuantu-sandbox.exe account-status --verify` 应报告 `accounts-missing`、`group-missing`、`firewall-missing`，`ready` 为 false；
   - `net user YuanTuSandboxOffline`、`net user YuanTuSandboxOnline`、`net localgroup YuanTuSandboxUsers` 都应失败；
   - 状态目录里没有 `setup_marker.json` 和 `credentials.json`，`read-grants.json` / `traverse-grants.json` 的 `grants` 为空。`account-status` 只看标记和凭据，清理后必须用 `--verify` 才能看到账户/WFP 的真实状态。
5. 如果管理员初始化无法完成（UAC 被拒、策略不允许建本地账户或改防火墙），隔离命令会停止并提示修复，不会回退到已移除的旧后端。CI 使用 `scripts/windows-account-ci.mjs setup` / `cleanup` 管理一次性 runner 的账户，`check:windows-sandbox` 及 `check:windows-desktop-sandbox` 要求账户旅程无跳过。
