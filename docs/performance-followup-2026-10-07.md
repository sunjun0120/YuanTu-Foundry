# 性能计划步骤 5～7 实施记录（2026-10-07）

继续 [既有性能计划](performance-optimization-2026-10-06.md#后续验证顺序)。本批交付可重复运行的实验入口、行为回归和测量结果；默认工具目录、PTC、模型推理及权限设置没有因实验变化。

## 步骤 5：六模块批处理与分阶段目录

入口：`node benchmarks/performance.mjs --pairs=3`。加 `--live` 后使用进程环境的模型配置；输出到新的 `.scratch` 实验目录，已有日志拒绝覆盖。`node benchmarks/analyze-performance.mjs <measurements.jsonl>` 可在不访问凭证或模型端点的情况下重新汇总。

每个样本创建独立合成工作区和 SQLite 会话：六个减法模块，依次读取、修复、执行同一 Node 校验。对照完整 native、阶段 native、阶段 PTC；阶段目录保留读取、精确修改／批量修改及命令能力。三个阶段共享文件观察记录与资源所有者，避免读取证据在阶段切换时丢失。

成功要求同时满足：六个文件逐字节匹配预期、实际命令返回 exitCode 0 和指定标记、三阶段完成、SQLite 重建用量一致。PTC 使用内核持久化的 `program.call.settled` 收据，程序自行返回成功 JSON 不能作为命令证据。拒绝审批和失败样本保留；只有同一配对两侧均验证成功时计算差值。摘要拒绝重复配对身份，其他对照配置不污染所选两种配置的失败计数。

本地 3 组／9 个样本全部完成。fixture 的 token 来自估计，明确标记 `fixture-estimate`，不能用作真实 API token 或费用证据。

真实模型为桌面当前的 DeepSeek-V4.1-Flash，用户批准的端点为 `https://llmapi.isrc.ac.cn/v1/chat/completions`。首轮 3 组／9 个样本完成 8 个，共 90 次实际 Provider 调用。阶段 native 的一个样本反复尝试 VM 不支持的 import／require，达到阶段上限而失败；未混入成功样本的分位数，配对比较仅有 2 个完整配对。

| ----------- | ---------- | -----------------: | -------------: | --------: | --------: |
| 完整 native | 3／0       |                 11 |         156406 |  91.44 秒 | 148.78 秒 |
| 阶段 native | 3／1       |                8.5 |          40613 |  63.44 秒 |  71.04 秒 |

完整→阶段 native 的两对墙钟差值为 -19.55／-100.16 秒；阶段 native→PTC 为 +53.76／+81.17 秒。两个成功配对不能证明通用延迟收益；同一机器上的并行验证、供应商缓存和模型自主调用路径均可能影响墙钟。

据真实失败补充 `run_code` 错误恢复提示：保留原错误，并指向该调用目录中可用的工具 SDK；仅当目录包含 `read_file` 时才提供其示例，不开放模块导入。实际 require／import 拒绝与随后 SDK 文件读取均完成 RED→GREEN 回归。

模块提示修复后的独立两组复验完成 5/6 个样本，共 64 次实际 Provider 调用。完整／阶段 native 均 2/2 成功，墙钟 P50 分别为 103.82／108.52 秒，输入 token P50 为 169535／61572；阶段 PTC 1/2 成功，成功样本为 67.04 秒、7 次请求、23220 输入 token。失败样本读取文件后调用 VM 不支持的 `console.table`，最终耗尽阶段预算；据此追加支持的 console 方法及直接返回数组／对象的提示，并完成真实进程 RED→GREEN 回归。最终 console 提示尚未做真实模型复验。两个版本分别保存源文件哈希和独立统计，不混合样本；这些结果不足以切换默认策略。

首个真实 pilot 样本暴露夹具误拒绝 `batch_edit`，保留为失败及中断试运行，不混入最终配对；修正后为相同六个合成文件放行真实批量修改，仍拒绝其他写入和命令。实验只向用户批准的端点发送合成任务、历史与工具定义；当前桌面密钥仅在进程内用于鉴权，不保存明文。三份实验日志共记录 169 次实际 Provider 调用，为中断中的一个请求保守预留后不超过用户批准的 180 次上限。实验前后模型配置文件及桌面 Local State 的 SHA-256 均未变化。

目录模式不限制模型一定使用某条调用路径：native 目录仍包含 `run_code`；PTC 组还增加显式批处理提示。因此阶段 native／PTC 对照包含目录表示、提示及进程成本的共同变化。三阶段边界由实验固定，不宣称具备自动阶段识别。

## 步骤 6：复用异步委派并先做独立工作

入口：`node benchmarks/performance-delegation.mjs --pairs=10`。

同一内核、真实父子会话和受控文件读取，对照阻塞 `delegate_task` 与 `wait:false` 后执行独立父任务。后者先用 `collect_subagents({waitMs:0})` 检查，尚未取得完整报告时最多再做一次有界等待；报告已收集则不增加等待轮次。每组保留实际父子执行区间、请求数和释放状态。

10 组交替 AB/BA 配对已完成，全部收集完整报告并释放父子会话。取消和子模型故障另有回归，失败不能计为完成。该实验使用 fixture Provider 和真实内核，证明区间重叠与收尾，不能证明真实模型延迟或费用降低。异步路径可能增加父模型轮次，远端等待较慢时收益可能被抵消。

本地阻塞／重叠路径墙钟 P50 为 473.40／341.83 毫秒，P95 为 561.86／361.57 毫秒；逐对差值 P50 为 -141.48 毫秒，10 对均有实际区间重叠。阻塞通常 5 次 fixture 请求，重叠 7 次；这些不是实际网络请求，不据此计费或推断真实模型收益。

保留 workflow 当前同步完成契约。本批没有将其提前返回；后台 workflow 仍需独立定义取消、预算、事件与结果回收后再实施。

## 步骤 7：长输出、多会话与故障压力

入口：`node benchmarks/performance-stress.mjs --duration-ms=60000 --concurrency=4`；实际一小时用 `--duration-ms=3600000`，两者按实际持续时间分别记录。

一个 Agent 请求在整个测试时段内分块输出 128 KiB；其他会话并发执行正常工具、工具失败后恢复、取消与 Provider 故障。记录 P50/P95、RSS／堆、进程 CPU 时间、数据库大小、释放状态及关闭后重新打开数据库的输出／统计一致性。fixture 不进行网络请求，资源仅描述该 Node 进程，不代表模型服务或外部工具进程。

短回归已覆盖流式输出、并发故障恢复、外部取消、边界拒绝和冷恢复。实际小时测试持续 3600.04 秒：一个长输出会话与四个故障测试会话，真实峰值为 5；2740 次测试运行全部符合预期，所有会话释放。128 KiB 输出及统计在关闭并重新打开数据库后完全一致，最终数据库为 18534400 字节，合成工作区已自动清理。

| 场景           | 次数 | 实际状态  |    墙钟 P50 |    墙钟 P95 |
| -------------- | ---: | --------- | ----------: | ----------: |
| 正常工具       |  685 | completed | 230.29 毫秒 | 310.04 毫秒 |
| 工具失败后恢复 |  685 | completed | 244.42 毫秒 | 328.34 毫秒 |
| 取消           |  685 | cancelled | 193.53 毫秒 | 261.94 毫秒 |
| Provider 故障  |  685 | failed    | 186.79 毫秒 | 256.72 毫秒 |

RSS 起点／峰值／终点为 124780544／297619456／297619456 字节；堆起点／峰值／终点为 38400816／115099416／96112224 字节。累计进程 CPU 用户／系统时间为 82.42／86.20 秒。四个会话持续追加历史，内存和数据库均增长；本次没有设置固定内存阈值，也没有强制 GC 或隔离历史规模，不能据此宣称内存有界或判断泄漏。

小时测试只验收本地内核、流、并发会话和故障语义，没有真实网络、外部工具进程或桌面渲染压力。所有异常样本及其预期状态保留，压力汇总的 `checksPassed` 表示预期恢复／取消／失败语义通过，不表示所有运行都成功完成。

最终独立审查发现：压力回调或某个并发任务抛异常时，长输出可能仍访问已关闭数据库。已增加内部取消与活动任务等待，初始化回调也纳入清理保护；四种异常路径均用独立 Node 进程完成 RED→GREEN 回归，核验没有延迟的未处理拒绝或残留工作区。小时证据来自审查前的正常路径版本；异常清理修复后完成短压力／取消／故障回归，没有把旧小时进程当作新异常路径的验证。

## 验证与证据

确定性行为测试包含真实文件与命令效果、审批拒绝、伪造收据、重复配对、日志保护、父子取消及冷恢复。受限环境阻止真实 PTC 进程树清理，允许子进程能力后同一测试通过；清理失败没有降格为成功。

原始证据保存在 `.scratch/performance-followup-20261007/`，脚本与回归随每项提交。实验运行与其他本机验证可能并行，墙钟受到系统负载影响；受控工具区间的重叠、文件效果与释放状态可独立核对。

最终 SDK 提示与审查清理修复后的全量回归 1507 项：1499 通过、8 跳过、0 失败。类型检查、构建、当前修改文件格式、文档事实／引用／国际化、13 条现有性能基准与编译客户端 4/4 通过。跳过项为未配置的真实语言服务器、Docker／sbx 及平台条件，不计为通过。
