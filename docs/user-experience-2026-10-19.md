# 普通用户真实模型体验记录

体验日期：2026 年 10 月 19 日，Asia/Shanghai。

对象：当前 YuanTu-Foundry 工作区，HEAD `2f9127a` 加现有未提交修改。重新执行 `npm.cmd run build` 成功后，使用真实 Electron 客户端、独立用户目录和独立示例工作区操作。复用了用户已保存的加密模型配置，默认模型为 `DeepSeek-V4.1-Flash-1017`，协议 OpenAI Chat Completions。没有使用模拟模型，也没有修改产品源码、个人配置或原有会话。

结论：基本分析和文件生成能够工作；交付入口、失败恢复和小任务效率仍会让普通用户承担较多操作。下列模型行为是本次样本的观察，不能据此推断所有模型或所有任务都会如此。

## 优先改进项

### 1 文件生成后缺少直接使用入口

实际要求“完成后给我可以直接打开的文件链接”。模型回复“已写好，可直接打开”，但页面里没有任何 `a` 元素；交付物记录也是 `li` 内的普通 `span`，没有按钮。点击“已编辑文件”能打开差异视图，用户仍需从文件树另行寻找成品。

代码依据：

- [renderer-session-panels.ts](../apps/desktop/renderer-session-panels.ts#L172) 只绘制交付物路径和描述。
- [markdown.ts](../apps/desktop/markdown.ts#L23) 的链接规则只接受 HTTP/HTTPS，本地文件链接会退化为文字。

建议：从已验证的工作区交付物提供“预览”“用默认应用打开”“显示所在文件夹”操作；文档任务优先展示成品，保留修改差异作为次级入口。不要直接放开任意本地路径协议。

### 2 Windows 默认模式遇到遗留锁后恢复不清楚

`node --test prices.test.mjs` 实际返回：

```text
Windows workspace ACL is leased by another process or needs recovery: .../workspace-owner.lock
```

只读检查发现锁里记录 `pid: 28100`，本机常规环境的进程检查未找到该 PID。该状态在体验开始前已经存在，不能把锁的形成归因于本次操作，也不能据此判定所有安装都会失败。未删除锁、未结束其他进程、未绕过权限。

模型在状态未变化时再次申请相同命令，普通用户没有得到明确的恢复入口。最终修复只能交付为“已修改、测试未运行”。

代码依据：[sandbox-windows.ts](../packages/tools/sandbox-windows.ts#L611)。

建议：识别并展示锁占用、遗留恢复和恢复失败这些状态，提供受控的检查与恢复流程；同一不可恢复原因不应反复进入审批和模型重试。

### 3 Word 的 PDF 预览存在可定位的构建集成问题

真实桌面调用 `office_preview`，输出根目录 PDF 时返回：

```text
Office automation script is missing from the runtime build
```

当前构建中：

```text
dist/packages/tools/host.bundle.js       存在
dist/packages/tools/automation.ps1       不存在
dist/packages/office/automation.ps1      存在
```

桌面优先启动 `dist/packages/tools/host.bundle.js`；Office 自动化按当前模块目录寻找 `automation.ps1`。打包后的模块目录变了，脚本仍复制到 Office 目录和 desktop 目录。

代码依据：[install-paths.ts](../apps/desktop/install-paths.ts)、[build-host-bundle.mjs](../scripts/build-host-bundle.mjs#L26)、[build-desktop.mjs](../scripts/build-desktop.mjs#L34)、[automation.ts](../packages/office/automation.ts#L117)。

建议：统一 bundle 的资源定位与复制规则，并对实际桌面 Host 的 Office 调用做验证。修复该路径后，仍需独立验证 Office/LibreOffice 可用性；本机 LibreOffice 另外返回不可用。

### 4 模型容易扩展任务范围，交付前的内容核对仍弱

只要求核对订单，却读取并尝试测试购物车代码；给老板的 Markdown 报告又包含 `prices.mjs` 的实现问题。Word 初稿还添加了来源没有声明的“人民币，含税口径同源数据”；模型随后自行删除含税表述，后续版本仍以“元”计价。源数据没有币种、日期和税务字段。

这属于本次默认模型的行为样本，不能直接归结为底层工具缺失。建议：要求报告事实与来源对应，未知币种、期间和税务口径明确标注；最终检查是否夹入任务之外的内容。

### 5 中文审批与文档阅读仍偏向开发者

命令审批显示英文 `Isolation: Runs under a restricted Windows token...` 和原始 JSON；中文文件差异头显示八进制转义文件名。Word 创建审批主要显示 `Create Office file via create`，普通用户无法从主界面直接审阅文档内容。

代码依据：[execution-policy.ts](../packages/tools/execution-policy.ts#L85)、[diff-view.ts](../apps/desktop/diff-view.ts)、[tools.ts](../packages/office/tools.ts#L121)。

建议：用中文说明具体将做什么、涉及哪个文件、为什么需要确认；保留原始参数作为展开详情。为文档写入提供内容或成品预览。

### 6 小任务消耗较多，过程说明不足

7 行 CSV 核对结束时，界面累计约 `39.3K tok`；接着生成简短 Markdown 报告后，两轮累计约 `85.8K tok`。这些数包含缓存命中，不能当作全价计费量或实际费用。

Word 任务在一次中途快照中已达到 12 步、149,379 个输入输出 token，其中 92,032 个为缓存输入。期间包括预览输出目录不存在、尝试用文本删除工具删除 DOCX（被工具拒绝）、预览引擎失败与改用其他方式。工具耗时还可能包含人工审批等待，不能当作纯计算耗时。

建议：缩小无关文件读取，减少重复工具定义与回读，预先确认文档预览能力，避免在确定的环境阻碍上反复尝试；给用户显示“正在核对数据”“预览能力不可用”等简短进度。

## 边界

- 已执行当前源码构建和真实桌面体验，没有运行全量测试或发布验收。
- 仅使用一个已配置真实模型，未进行多模型质量排名。
- DOCX 已创建并回读文本，未完成真实分页渲染，不能声称符合一页排版。
- Word 任务在待审批时点击停止，快照立即变为 `running: false`、`status: cancelled`、审批数为 0，其他活动任务为空；停止操作有效。后续重新输入简短追问后可以正常回答，并遵守不调用工具的要求。停止后立即输入的第一条草稿出现过清空现象，尚未稳定复现，未列为确定缺陷。
- 模型在追问回答中将 Word 预览失败归因为缺少 Word 渲染引擎；实际捕获的是自动化脚本定位失败，不能据此确认 Word 安装状态。LibreOffice 不可用则有单独的工具结果。
- 测试代码已修改，但测试命令被现有 ACL 锁阻挡，不能声称测试通过。
- 最初受限环境的 Electron 启动失败，以及独立自动化内核的启动错误，均没有计为产品缺陷。
- 临时体验客户端、用户目录、示例文件和截图在体验结束后清理；保留本记录。
