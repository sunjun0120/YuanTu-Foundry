## 4. 仍未修复的开放项

以下 5 条本轮**未改**：要么需要跨进程/端到端 fixture 才能验证，要么改动面落在关键路径而收益与风险不匹配。均已给出触发条件与建议。

| #   | 位置                                                                                                                                                           | 严重度 | 触发条件与后果                                                                                                                                                                                                                               | 建议                                                                                                                       |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| O1  | [`packages/mcp/oauth.ts`](../packages/mcp/oauth.ts)（`observe`）                                                                                               | 中     | `.well-known` 响应 `content-type` 含 json 时 `await response.clone().json()` 无界：服务器缓慢滴送 JSON 时 `fetch` 调用方（含 `auth()`）被拖住。`observe` 必须在交还响应前完成（注释已说明原因），因此不能简单改成不等待                      | 给解析加与 `MCP_CLOSE_TIMEOUT_MS` 同量级的有界竞速，超时只用已读到的 header 结论                                           |
| O2  | [`packages/providers/discovery.ts`](../packages/providers/discovery.ts)                                                                                        | 中     | 端点发现没有自己的截止时间，[`apps/cli/main.ts`](../apps/cli/main.ts) 调用时也不传 signal：不响应的 endpoint 会让命令挂到外部超时                                                                                                            | 加一个可配置截止时间（并与传入 signal 组合），CLI 侧传入 signal                                                            |
| O3  | [`packages/client/host-client.ts`](../packages/client/host-client.ts)（`launch`）                                                                              | 中     | `launch()` 里 `this.spent = null` 丢弃上一次故障的 transport，而 `close()` 只处理 `this.transport ?? this.spent`：旧 Host 收到 `end()` 但仍在收尾时被遗忘，既不等待也不 `kill`，可继续占用工作区锁与 pty 子进程；每次 `recoverHost` 再丢一个 | `launch()` 启动新进程前先 `end()` 旧 spent 并在 `shutdownTimeoutMs` 内有界等待，超时 `kill()`；需配一个假 transport 的单测 |
| O4  | [`apps/desktop/main.ts`](../apps/desktop/main.ts)（退出路径）                                                                                                  | 低-中  | 退出时 `await sandboxInitializing` 无上限（`sandbox-setup.ts` 有意用 `timeout: 0`）：原生沙箱初始化不返回时退出被卡住，只能从任务管理器结束进程                                                                                              | 退出路径改用有界等待，超时后按"清理未确认"上报并继续退出                                                                   |
| O5  | [`apps/desktop/renderer-background.ts`](../apps/desktop/renderer-background.ts)、[`apps/desktop/renderer-subagents.ts`](../apps/desktop/renderer-subagents.ts) | 低     | 按钮在一次**可被拒绝**的 IPC 调用前被禁用，返回拒绝后没有恢复：一次失败后按钮永久不可用                                                                                                                                                      | IPC 的 `finally` 中恢复可用状态（或仅在成功路径禁用）                                                                      |

另有一条已知设计取舍（**不是缺陷**，仅记录）：`SessionEventJournal.transaction()` 是 join 而非嵌套，因此"事务内 catch 后继续"无法回滚已写入的部分。R15 已把最严重的触发路径（先写后读）改成"读前置"；若要根治，需要真正的 SAVEPOINT 嵌套。

## 9. 首轮等待与实时进度

用户确认参考 Codex 的事件式反馈修改后，自动标题改由 Host 在后台发起；正式回答不再等待标题完成。初始实现保留 8 秒截止与失败回退；后续标题兼容修复改为 30 秒（见 §10），手动命名仍优先。Host 退出取消标题请求，并在关闭数据库前结算任务；生成成功通过 `session.title.updated` 独立刷新名称，包括回答已完成或用户已切换会话的情形。

## 11. 问答范围与重复查询收敛

按用户确认的建议，在系统提示中明确：可由现有对话或稳定通用知识回答的问题优先直接作答；依赖项目现状或时效信息的事实仍需验证。项目检索先定位相关路径、符号和邻近代码，有具体缺失事实才扩展；独立检查合并执行，有足够证据后及时回答。该部分是模型行为规则，不是基于关键词强制禁用工具，也没有额外调用分类模型。

新增每轮查询证据比较，覆盖 `read_file`、`list_files`、`search_files`、`git_status`、`git_diff`，也读取 `run_code` 实际调用的内部工具与程序计算结果（排除耗时尾注），同一文件产生新计算结果仍算新证据。忽略调用 ID 和参数对象的键顺序，比较参数及完整结果的哈希。首次取得结果后，连续两个无新信息的重复轮次会提示收敛；再重复一轮，下一次模型请求只提供已有证据、不提供工具。若提供商仍返回工具调用，则不执行，结算未执行结果并以 needs_review 停止，不伪造成功。

每个运行最多保存 256 个查询指纹。写入、轮询、未知工具、额外上下文或目标变化会使比较失效；用户追加输入、权限变化、计划批准和验收修复会恢复正常工具能力。复杂任务持续获取新证据时没有固定轮数上限。查询收敛也会停止自动目标续跑，但不会把尚未实现的目标标记完成。
