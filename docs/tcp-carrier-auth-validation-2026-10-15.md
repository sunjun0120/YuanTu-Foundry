# TCP Agent Host 认证与输入边界验证（2026-10-15）

本批接续“逐步修复问题”，处理审计队列中的 TCP carrier。保留工作区已有改动，不提交 Git，不调用真实模型，不执行安装、签名或发布。

## 行为与兼容性

- 默认桌面 stdio 启动方式继续使用父子进程管道，不要求 TCP 凭据。
- 显式使用 `--listen` 时，仅允许字面量 IPv4 回环地址 `127.x.x.x`。拒绝主机名、通配地址和外部地址；启动参数校验在打开数据库前完成。
- TCP 必须通过可信启动环境传入 `YUANTU_HOST_TOKEN`，要求 32–512 个 ASCII 字母、数字、下划线或连字符。调用方应使用随机生成的凭据，不从工作区读取。现有 TCP 调用方需要同时更新服务端环境和客户端 `authToken` 选项。
- TCP 的首个请求必须是带 `params.authToken` 的 `host.info`。认证成功前不会进入 RPC 分发、取得 Host 所有权或启动依赖 carrier 的后台调度；成功后移除请求中的凭据再交给 RPC。客户端仅在连接模式的初始握手发送凭据。
- 认证前缀最多 4096 字节，包含没有换行的输入；认证期限 5 秒，同时最多容纳 8 个待认证连接。认证后复用有界 JSONL 分帧器，单帧最多 16 MiB，同样限制没有换行的输入。
- 凭据比较使用长度检查与 `timingSafeEqual`。凭据在设置注册中标记为敏感项，不进入工具子进程环境；客户端对不可信对端回显的显式凭据也执行脱敏。
- 被拒绝连接提前安装 socket 错误处理，避免连接重置导致 Host 异常退出。关闭等待认证的 Host 会释放监听和挂起的 attach。

该入口不提供 TLS，也不开放直接远程监听。需要跨机器使用时，应由调用方提供受保护的外部隧道；本批仅验证回环载体。未据此宣称 Windows/macOS 原生沙箱、安装或发布能力已验收。

## 验证证据

配置与未认证 RPC 回归先观察到失败，再修复实现。真实 Host 测试确认错误凭据、缺少凭据以及首个方法错误均不会创建会话；拒绝后合法客户端仍能连接。启动测试确认无凭据、格式错误和非回环监听均在创建数据库前失败。

独立只读审查发现一个连接竞争：多个连接先进入待认证集合，后认证的连接可能覆盖已经取得所有权的客户端。增加认证成功后、同步设置所有权前的占用检查。确定性回归先填满 8 个待认证连接，再依次认证两个，确认第二个返回 `HOST_BUSY`，第一个仍能取得后续 RPC 响应。该回归修复前失败、修复后通过；审查复核未报告本批剩余 P1/P2 阻塞项。

输入限制另做变异核验：临时放宽认证前缀和认证后帧上限，对应两项回归均失败；恢复 4096 字节与 16 MiB 限制后，两项通过。其他覆盖包括 UTF-8 与流水请求、空闲认证超时、拒绝连接立即重置、挂起认证关闭，以及不可信对端回显凭据的脱敏。
