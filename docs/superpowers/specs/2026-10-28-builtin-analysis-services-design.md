# 内置代码分析服务接入设计

## 背景与目标

Agent 是通用编程 Agent，同时内置源码审计/合规分析能力。用户不提供分析对象、也不调用分析服务时，它不会主动使用分析服务，其余行为与通用 Agent 一致（服务启用时工具目录会多出内置服务的入口，这正是产品功能本身）。用户添加源码包、给出 GitHub 仓库或提出分析要求时，它按需使用分析服务工具，对目标做检查分析（SBOM、许可证、漏洞、可维护性等），并输出报告。分析能力由后端团队以远程 MCP 服务（HTTP）提供，按模块划分工具。目标：用户安装后无需任何配置即可调用这些能力，且分析能力的存在不改变通用使用方式。

已确认的前提：

- 后端是远程 HTTP MCP 服务。
- 本地源码包走后端单独的 HTTP 上传接口；GitHub 仓库由后端自行拉取。
- 分两阶段交付：第一阶段不做登录，后端也不鉴权用户，先跑通整体流程；第二阶段再加用户登录与后端鉴权（见第 9 节）。
- 后端工具同步、异步两种都有。
- 后端产出标准报告，agent 在此基础上做定制化解读报告。

现有 MCP 实现只读取工作区的 `.yuantu/mcp.json`，以 `mcp_<id>_list_tools` / `mcp_<id>_call_tool` 两跳代理调用，每次调用按 `external` 审批，调用超时固定 30 秒。这些都不适合内置可信服务，因此采用「把内置服务的工具注册为原生工具」的方案。

## 不在范围内

- 用户登录与后端鉴权（第二阶段，第 9 节只记录预留方案）。
- 把不可信仓库直接作为工作区打开时的整体隔离（不加载其 `AGENTS.md`、Skills、扩展与 MCP 配置）。分析不需要这样打开，推荐路径见第 5 节「分析对象的信任边界」；整体隔离影响面大，单独设计。
- 在工作区之外登记分析对象：第一阶段的分析对象只能来自工作区内路径，或桌面端复制进 `analysis-inputs/` 的源码包。
- 私有 GitHub 仓库授权。
- MCP 原生 Tasks 机制（作为后续升级路径）。

## 1. 结构与配置

新增 `packages/builtin-services`，分层位于 `packages/mcp` 之上、`packages/catalog` 之下，并登记到 `scripts/check-layers.mjs` 的 `LAYERS`。复用 `packages/mcp` 的关闭等待（`closeWithin`）、schema 复杂度检查（`validateSchemaComplexity`）与输出截断；连接由本包自持，不用 MCP 的会话池。

**内置清单**：清单是代码里的常量（`manifest.ts`），随代码签名分发，不由工作区提供。正式地址 `PRODUCTION_BASE_URL` 由构建期内置；它还是 `undefined` 时，安装包不注册任何内置服务工具。每个服务包含：

| 字段             | 说明                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| `id`             | 服务 ID；只用于用户目录里的缓存文件名                                        |
| `baseUrl`        | origin 加可选路径前缀，不带结尾斜杠；必须 HTTPS                              |
| `mcpPath`        | MCP 端点路径（拼在 `baseUrl` 下），默认 `/mcp`                               |
| `uploadPath`     | 源码上传接口路径，默认 `/upload`                                             |
| `toolPrefix`     | 注册到 agent 的工具名前缀，如 `scan`                                         |
| `callTimeoutMs`  | 同步工具调用超时，默认 300000                                                |
| `taskTools`      | 异步任务的状态、结果、取消三个后端工具名                                     |
| `maxTools`       | 注册工具数上限，默认 64                                                      |
| `maxSchemaBytes` | 注册工具 schema 的总字节上限，默认 256 KiB（工具常驻，这一条守住提示词成本） |
| `maxUploadBytes` | 上传上限，第一阶段为常量 200 MB                                              |
| `maxResultChars` | 单次结果保留的字符上限，默认 8 × 1024 × 1024（按字符切，不按字节）           |
| `maxReportBytes` | 单个报告下载上限，默认 50 MB                                                 |

工作区 `.yuantu/mcp.json` 不能新增、覆盖或禁用内置服务：内置工具不是 MCP 代理，名字也不走 `mcp_` 前缀，与工作区配置的 `mcp_<id>_…` 两跳代理不可能同名；服务地址只来自构建产物。

**开关**：`YUANTU_BUILTIN_SERVICES=0` 关掉整个能力（不读缓存、不建连接、不注册工具）；缺省开启。开发构建可用 `YUANTU_BUILTIN_SERVICES_URL` 覆盖地址（允许回环 http），安装包由桌面设置 `YUANTU_PACKAGED` 后忽略该变量。非产品入口（测试隔离环境、`scripts/docs-facts.mjs`、`benchmarks/*`）一律把它设为 `0`，否则 `npm run check` 的结果会取决于运行者机器上的缓存与网络。

**请求入口唯一**：发往内置服务的所有请求（MCP 传输、源码上传、报告下载）都经同一个 `ServiceRequester` 生成请求头与选项。第一阶段不带任何鉴权头；第二阶段在这里注入令牌（见第 9 节）。

**路径句柄平台限制**：当前桌面源码包暂存、上传与报告写入的防替换句柄由 Windows PowerShell / Win32 提供；其他平台或 PowerShell 不可用时拒绝这些操作，不降级为普通路径读取或写入。后续为 macOS 等平台接入等效能力后再启用。

**生命周期**：连接是进程级共享的一个（远程 HTTP、本地无会话状态，按会话开连接只是重复握手），Host 关闭时随 `closeAllToolResources` 关闭。一次调用的失败（取消、超时）不急切关闭这个共享连接：只有最后一个在途调用结束时才回收，运输层自报 `onclose` 时忘掉连接、下次重连。

## 2. 工具注册与权限

- 连接后调用 `tools/list`，每个后端工具注册为 `<toolPrefix>_<后端工具名>` 原生工具，`inputSchema` 原样使用，发送前用 ajv 本地校验。
- schema 必须用注册表的同一个编译器（`packages/tools/registry.ts` 导出的 `compileToolSchema`，`strict: true`）。用一个更宽松的 Ajv 预检、再让注册表编译，会让「预检通过但注册抛错」变成整次运行失败，而不是跳过这一个工具。
- 名称非法或过长、schema 超限或编译失败的工具跳过；schema 编译失败与 schema 预算耗尽各记一条日志（重复的名字不记，后端分页返回重复是正常的）。超过 `maxTools` 或 `maxSchemaBytes` 的部分不注册。内置工具常驻工具列表，不放进延迟加载组：代码分析是产品主功能，代价是每个请求都带着这些 schema，因此由上面的两个上限守住提示词成本；这样也不必改延迟目录的分组机制。
- 权限依据 MCP 工具注解：`readOnlyHint: true` 不声明权限（免审批）；其余按 `external` 审批。为不改变本次运行的作业状态，内置工具一律独占执行，不与同批调用并行。
- 最近一次成功的工具列表缓存在用户目录（按服务地址校验，`savedAt` 必须是可解析的时间）；启动时先按缓存注册，Host 启动即预热，缓存超过 10 分钟时在后台刷新，下一次运行生效。首次安装后的第一个会话可能只有上传/下载工具（预热尚未完成），从第二次运行起稳定。
- 不订阅 `notifications/tools/list_changed`：列表在下次运行生效，与订阅的效果相同、实现更简单。
- 断网或后端不可用时，已缓存的工具保持注册，调用返回明确错误，不让工具消失。

## 3. 代码输入

**原生工具 `analysis_upload_source`**（`external` 审批）：

- 参数为工作区内文件或目录路径。`.zip`、`.tar.gz`、`.tgz` 文件原样上传，不在本地解压。
- 目录在本地打成 zip：复用文件工具的凭据排除规则，并排除 `.git` 等版本控制目录、依赖目录、`.yuantu`、`analysis-inputs`、`analysis-reports`；审批后验证完整祖先链与文件身份，并保证验证和读取期间路径替换不能越界；链接、junction 或文件发生变更时拒绝。归档也须复核身份及实际大小，目录限制实际读取总量；无法保证边界的平台拒绝上传。打包清单（文件数、总大小、跳过的条目数）写入审批描述。
- 以 multipart（字段名 `file`）调用清单中的上传接口，返回 `project_id` 供后续分析工具使用。
- 大小以清单常量 200 MB 为准，超出在本地拒绝；支持取消（中止请求），第一阶段不报告进度。
- 上传失败时后端响应体只写日志，工具结果只给 HTTP 状态。

**桌面入口**：输入框只接收源码包（`.zip` / `.tar.gz` / `.tgz`）。拖入或选择文件时，渲染层拿到文件路径，主进程通过受保护的文件句柄读取并独占写入当前项目工作区的 `analysis-inputs/`（重名编号），不经渲染进程搬运字节；粘贴的文件没有路径时才退回按字节写入。主进程只接受当前打开项目（含多窗口）的工作区，只复制常规文件、不跟随链接、不读取内容进对话。

**GitHub**：由后端拉取工具（第 2 节自动注册）接收仓库 URL 与可选 ref。agent 不解析通用工具的哪个参数是仓库地址；限制写进后端接口约定：导入工具必须只接受 `https://github.com/<owner>/<repo>`，拒绝其他主机。

## 4. 异步任务、结果与报告

**异步任务**：慢工具立即返回 `{ task_id, status }`（放在 MCP `structuredContent` 里）。agent 把它登记为新的作业类型 `analysis`，作为 `packages/tools/jobs.ts` 作业控制面的生产者：

- `job_list` 列出分析任务与状态；`job_output` 调用状态工具，支持等待，等待期间按递增间隔轮询，完成后调用结果工具取回结果；`job_kill` 调用取消工具，幂等。三个工具的描述都提到这一类作业。
- 同一任务的两个 `job_output` 共享一次在途轮询，不重复请求后端；结果成功获取并持久化后才进入 completed；获取失败保持可重试。取消与轮询按任务协调，取消成功后旧轮询不得覆盖终态，并发取消只发一次，失败不标记已取消。
- 任务记录写到工作区 `.yuantu/analysis-tasks.json`：单条记录保留的输出有上限（1,000,000 字符）并在超出时报告 `truncated`，写盘按最新快照合并，避免每次轮询重写整个文件。Host 重启后从该文件找回并继续查询。

**大结果**：超过输出预算的结果复用现有溢出落盘，模型拿到摘要与路径，按需 `read_file` 分段读取。

**后端标准报告**：后端在工具结果中以 MCP `resource_link` 返回报告文件。agent 用独立的写入工具 `analysis_download_report` 下载到工作区 `analysis-reports/<project_id>/`，记入文件改动日志（返回的 `change` 带 journal id，改动列表与撤销可用），再经 `present` 交付。只接受 PDF、DOCX、HTML，以及 JSON、XML（CycloneDX / SPDX 即其 JSON、XML 形式）；链接路径的最后一段是文件名，扩展名必须与 content-type 一致；限制单文件大小；下载地址必须与内置服务同源。任何建目录或写文件之前验证完整祖先链，安全地逐层创建并防止链接或 junction 替换；不能保证边界时拒绝写入。

**定制解读报告**：新增内置技能「代码分析报告」，规定报告结构，并要求所有数字与结论引用后端数据；技能开头写明「看不到 `analysis_upload_source` 时不要使用本技能」。agent 按用户要求用 `office_create` 生成定制 Word 报告，结尾列出数据来源与后端报告原件。

## 5. 安全

- 后端返回的工具描述、结果与报告内容一律视为不可信数据。
- 内置服务地址必须 HTTPS（开发构建另允许回环）；请求 `redirect: 'error'`，不得离开服务的 origin。
- 报告只从内置服务同源地址下载，拒绝后端结果中指向其他主机的链接；报告文件名与类型都要匹配。
- 第一阶段后端不鉴权，服务地址应部署在受控网络或仅用于联调；正式对外发布前必须完成第二阶段。
- `analysis_upload_source` 是代码离开本机的主要入口，审批写明内容、文件数与大小，打包排除凭据文件；所有内置工具自身仍是 `external` 审批（只读工具除外）。
- 桌面端复制源码包时，路径来自渲染进程，主进程只把它当作「把一个常规文件复制到当前工作区的 `analysis-inputs/`」的请求：不跟随链接、只写该目录、不读取内容。

### 分析对象的信任边界

通用模式下，工作区是用户自己的代码，按现有规则可信；分析的目标往往是第三方代码，不可信。信任边界因此跟着分析对象走，不跟着会话走：同一个会话可以先做通用编程、再做分析，工作区的信任状态不变。

- **分析对象不是工作区**：源码包、文件夹与 GitHub 仓库是被检查的数据。agent 只对它打包上传，不加载其中的 `AGENTS.md`、Skills、扩展、钩子与 MCP 配置，不在其中执行命令，也不读取其内容进对话；分析结论只来自后端结果。
- **桌面复制进来的源码包**：只是工作区 `analysis-inputs/` 下的一个归档文件，agent 看到的是路径；归档不会被解压，也不会被当作项目配置读取。
- **GitHub 仓库**：由后端拉取，本地不落代码，天然满足上面的边界。
- **工作区内的分析对象**：用户分析自己项目里的代码时，按工作区现有信任规则处理，不额外隔离。
- **推荐路径**：分析第三方代码时，把源码包作为附件添加（主进程复制到 `analysis-inputs/`），不要把仓库作为工作区打开。直接打开时，钩子仍受现有工作区信任确认约束，其余配置的整体隔离不在本期范围。

## 6. 错误处理

| 情况                       | 行为                                                                                                 |
| -------------------------- | ---------------------------------------------------------------------------------------------------- |
| 断网 / 后端不可用          | 返回「服务暂不可用」；已缓存工具不注销；异步任务保留可再查                                           |
| 同步调用超时               | 返回超时错误；异步任务不受影响                                                                       |
| 参数校验失败               | 本地拒绝，指出出错字段                                                                               |
| 后端返回非法结果或错误正文 | 返回通用错误，原始内容只写日志（`stderr`），不进工具结果；包括 MCP 正常响应中 `isError: true` 的正文 |
| 后端工具的 schema 无法编译 | 跳过该工具并记一条日志；不抛出，不影响其余工具与本次运行                                             |

## 7. 需与后端约定的接口

1. 上传接口：路径、multipart 字段名 `file`、size 上限（第一阶段为 agent 侧常量 200 MB，后端需接受同量级）、返回 `{ "project_id": "<id>" }` 的格式与错误码；`project_id` 字符集 `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`（会被用作目录名，不能含 `:` 或 `..`）。
2. GitHub 拉取工具：名称与参数（URL、ref）；只接受 `https://github.com/<owner>/<repo>`，拒绝其他主机（防服务端请求伪造）。
3. 异步任务：慢工具在 `structuredContent` 返回 `{ task_id, status }`，`task_id` 匹配 `[A-Za-z0-9._:-]{1,96}`；状态、结果、取消三个工具的名称、参数（`task_id`）与状态取值 `queued | running | completed | failed | cancelled`。
4. 工具注解：只读工具标注 `readOnlyHint: true`；schema 必须能被 Ajv 8 的 strict 模式接受（不要用 `format`、`nullable` 或自定义关键字，也不要声明 2020-12 的 `$schema`——注册表用 draft-07 的 Ajv 编译）。
5. 报告文件：以 `resource_link` 返回，下载地址与 MCP 端点同源；URI 最后一段是文件名，扩展名与响应 content-type 一致（`.pdf` / `.docx` / `.html` / `.json` / `.xml`）。
6. 鉴权：第一阶段不需要；第二阶段的约定见第 9 节。

## 8. 测试

- 单元测试：清单解析、开关与地址校验；保留前缀冲突（工具名按两跳 MCP 命名，不会与内置名冲突）；权限分类；工具名映射与 `maxTools` / `maxSchemaBytes` 上限；schema 用注册表同一个 Ajv 编译（带 `format` 的 schema 被跳过而不是让运行失败）；作业状态流转、结果失败后重试、取消与在途轮询的竞态、并发取消去重、并发 `job_output` 去重、单条输出上限、持久化与重启找回；请求构造函数是唯一出口（同源、禁止重定向、请求头）；目录打包排除凭据、版本控制、依赖、`analysis-inputs`、`analysis-reports`，审批后替换父目录 junction、文件身份和大小的竞态；GitHub URL 的校验写在**后端契约**里（agent 不解析通用参数，这一条由后端测试覆盖）；报告下载规则（同源、类型/扩展名、已有文件、建目录前拒绝工作区外 junction）；缓存损坏（不可解析的 `savedAt`）被忽略。
- 集成测试：本地假 MCP 服务加 HTTP 上传接口，覆盖上传 → 同步分析 → 异步分析 → 取消 → 重启（新实例读同一文件）→ 下载报告；以及「后端 schema 被注册表拒绝时工具目录仍能建立」。
- 桌面测试：`stageSourceArchive` 的路径复制、字节回退、重名编号、链接拒绝，以及附件控制器分流。
- 桌面 smoke：本期不加新的 Electron smoke（第 12 条调整）；将来新增时必须登记到 `package.json` 的 `smoke:desktop`。

## 9. 第二阶段：登录与鉴权（预留）

第一阶段跑通后再设计与实现，这里只记录已讨论的方向。**改动点不是一个**：请求头注入和 401 重试分属两层。

- 请求层：`ServiceRequester` 的 `headers()` 改为异步（或在构造请求前解析令牌），接入令牌来源接口 `getAccessToken(options?: { refresh?: boolean }): Promise<string | undefined>`，放入 `Authorization: Bearer`；返回 `undefined` 表示未登录。因为令牌是异步取回的，`headers(): Record<string, string>` 的同步形态在第二阶段必须改。
- 客户端层：`AnalysisClient` 收到 401 时以 `{ refresh: true }` 再取一次并重试一次，仍失败返回「请先登录」；未登录时工具保持注册，调用返回同样的提示。重试只能在这里做，请求层看不到 MCP 错误码。
- 工具在 Host 进程执行，登录状态在桌面主进程：Host 经 `packages/carrier` 命令词表新增的一条受校验请求向桌面取令牌，令牌只在内存中传递，不写入环境变量、磁盘、日志、会话事件或工具结果。CLI 单独运行时没有登录状态。
- 后端约定：接受 `Authorization: Bearer <用户令牌>`，未授权返回 401；报告下载接受同一令牌。
- 单一 origin 的规则意味着第二阶段不做 OAuth 发现：令牌只来自桌面。
