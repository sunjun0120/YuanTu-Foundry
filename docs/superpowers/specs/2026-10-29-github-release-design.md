# GitHub 安装包自动发布

用户已选择：推送版本标签后，由 GitHub Actions 自动测试、打包并发布安装包，供用户从 Releases 下载。

- 沿用现有 Windows x64 构建及安装、升级、回滚验证；全部成功后发布该次运行的安装包和 SHA-256 清单。
- 标签必须严格等于 `v` 加上 `package.json` 的版本；在安装依赖前检查。
- 普通提交不触发此流程；手动运行仅生成 Actions 构建产物，不发布 Release。
- 构建任务使用只读权限，独立发布任务才获得 `contents: write`，使用内置 `GITHUB_TOKEN`。
- 发布依赖现有标签，不自动创建或移动标签，不覆盖已有 Release。沿用现有升级验证的要求，自动发行仅接受三个数字分量的稳定版本。
- README 写明发版命令、下载入口和私有仓库的访问限制；本次不实际推送标签或发布版本。

## 方案

用户选择版本标签触发，避免每次提交都成为正式发行。保留 Actions artifact 用于手动验证，在其后添加 Releases 发布任务；只保留 artifact 无法提供面向用户的版本下载页。macOS 发行和签名不在本次范围内。
