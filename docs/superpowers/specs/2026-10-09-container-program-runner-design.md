# 下一批设计：容器内程序 runner

状态：用户已确认继续；先实施独立 runner 与启动握手，容器接线仍待真实环境验收。上一批凭据保护与文件权限边界已完成定向验证。

## 目标与范围

让 `run_code` 和同步 `workflow` 在显式选择的 Docker/sbx 后端执行 guest JavaScript，而不是拒绝或退回 host。模型仍通过现有工具 RPC 读取工作区与申请修改；容器内程序不获得宿主密钥、任意路径挂载或新的审批权。

本批仅补程序 runner，不顺带开放容器模式 Git、PTY、LSP、stdio MCP，也不新增后台 workflow 或自动恢复副作用。工作流阶段持久化作为后续独立批次，避免把运行后端和数据库事件契约一起改动。

## 当前证据

- `packages/tools/code-process.ts` 的 `startCodeProcess` 当前对 docker/sbx 明确拒绝，并禁止 host fallback。
- 现有 host/Windows runner 通过独立 Node broker、Worker、JSONL 消息和工具调用回执运行。guest 线程堆上限、日志和 RPC 上限已有实现。
- `SandboxProvider` 当前的普通命令路径没有可信 runner 文件的独立装配契约。Docker 工作区是只读挂载；sbx 使用隔离工作区快照。不能把宿主绝对路径当成容器内路径，也不能为加载 runner 而放开整个安装目录或 `.yuantu`。
- 本机可以解析 `sbx.exe`，当前 PATH 未解析到 Docker CLI；这仅是命令入口检查，不能证明服务、镜像或真实隔离可用。

## 方案选择

推荐独立、版本明确的 runner 镜像／模板，内含编译后的 broker、worker 和最小运行依赖。部署方预先安装可信运行产物，运行时不自动拉取或安装；不可用时返回明确错误。

另两个方案不采用：把整份宿主安装目录挂载给容器会扩大暴露面；运行前把 runner 混入用户工作区会污染文件日志，并与内部目录隐藏和 sbx 快照生命周期冲突。

Docker 和 sbx 必须分别验证自身的镜像／模板启动与标准流契约，不能因为使用同名接口就假定参数或隔离语义相同。先交付 Docker 接线及真实验收，再接通经验证的 sbx 路径；未通过验收的后端保留当前明确拒绝行为。

## 运行与授权契约

1. 在模型脚本执行前核对后端、工作区身份和部署方指定的 runner 版本；配置由可信启动设置提供，不接受 guest 传入镜像、挂载或进程参数。
2. 容器只运行可信 broker／worker 产物，工作区及宿主其他目录不直接开放给 guest。文件访问通过工具 RPC，因此沿用上一批的凭据保护、工作区限制、审批和文件日志。
3. 复用现有消息校验：限制帧／总输出、调用数量和工具名，拒绝重复 ID、非法参数及最终结果之后的消息。容器 CLI 的诊断必须与协议标准流分离；无法维持这个契约的后端拒绝执行。
4. 容器进程限制网络和直接文件写入；文件工具的审批权限仍独立计算。容器内有模型脚本及已明确传入的数据，但不继承宿主 API key、MCP token、任意环境变量或 Docker 控制套接字。
5. 当前工具目录、schema、审批与执行策略仍由宿主维护。运行中切换权限继续按原有每调用核查处理，不能通过旧 guest 连接获得已撤销权限。

## 取消、故障与资源回收

- 取消准备、进程启动失败、脚本错误、超时、RPC 断线和正常完成都进入同一收尾路径；停止容器并等待已知进程结束，再清理创建的资源。
- 清理失败返回失败，不把仍存活的容器报告为成功，也不删除不属于本次运行的资源。
- 容器断线后保留已知工具调用收据；未知效果不自动重放。同步 workflow 保留现有等待／取消子代理契约。
- 不因后端失效自动选择 host，也不通过放宽网络、挂载或凭据预检查让测试通过。

## 修改边界

- 新增容器 runner 部署产物、版本清单与可信配置；纳入开发构建及 Windows 打包的可用性检查。
- 在 `code-process.ts` 分离后端启动与既有 RPC broker 生命周期；保留 `validateCodeMessage` 的统一校验。
- 扩展后端契约以显式描述可信运行产物与清理责任；避免用普通命令字符串拼装镜像、路径或挂载。
- 新增隔离后端回归与真实容器验收入口，更新配置文档和已知边界。保留当前工作区并行进行的 Host／storage／renderer 重构。

## 验收标准

- 实际容器内 `run_code` 能计算并通过 RPC 读取普通文件；同目录凭据读取失败；经拒绝的写入没有文件效果，经批准的写入沿用日志与撤销。
- 实际容器内同步 workflow 能编排子代理、收集结果；取消后子代理及容器不继续产生延迟副作用。
- 实测直接写宿主／工作区、网络访问和获取宿主凭据的尝试被相应边界拒绝；不把 VM 或 Node Permission Model 当作完整恶意代码隔离证明。
- 缺镜像、版本不符、服务不可用、启动中取消、畸形 RPC、清理失败均有回归；没有 host fallback。
- 开发过程中运行后端、程序 RPC、审批／文件及 workflow 相关回归。批次结束对固定源码状态运行一次完整门禁；真实服务未运行时明确标注尚未验证，保持相应后端的拒绝行为。
