# 孤立工作区绑定的维护与恢复（2026-10-16）

本批接手工作区中已有的存储、协议和回归测试雏形。用户确认由本 agent 接着完成；保留既有工作区改动，不提交 Git。这里记录最初完成的 Host 维护 API；随后补齐的桌面入口和关联修复见[收尾记录](remaining-audit-repairs-2026-10-16.md)。

## 问题与行为

删除会话会把工作区绑定的 `session_id` 置空，保留目录和导出结果。这有助于保存未合并工作，但原维护 RPC 要求会话存在，导致这些绑定无法再通过 API 管理。接手时存储与协议已有部分实现，RPC 未接通，三个基础回归均失败。

现在 `workspaces.orphaned` 返回当前项目的孤立 worktree 绑定、目录诊断和按绑定保存的结果。默认列出仍需清理的绑定；`includeRemoved: true` 也返回已移除目录的持久恢复记录，客户端重启后仍能找到恢复目标。

`workspace.archive`、`workspace.remove`、`workspace.restore` 接受互斥的 `sessionId` 或 `bindingId`。会话入口继续检查会话归属；绑定入口仅接受当前项目、`sessionId=null`、`kind=worktree` 的记录，拒绝其他项目、活动会话绑定、未知绑定以及双 ID 请求。维护过程中在操作租约内再次检查孤立归属。

维护写入使用每次调用的实时策略：会话入口读取当前会话选择，孤立绑定使用当前 Host 默认选择。沿用现有 Git 元数据能力约束，仅 `host` + `workspace-write` 可以执行；其他策略返回 `WORKSPACE_POLICY_UNSUPPORTED`，不改变用户选择。

归档、移除和恢复继续走已有 `WorkspaceManager` 路径：操作租约、Git 身份检查、移除前快照、内容复核与恢复记录均保留。没有自动删除工作目录。导出结果和此后尚未导出的实际文件分别保留，恢复测试核对最终文件字节。
