**Corrections:** (1) Severity: medium → low. This is disk/inode usage in the per-user OS temp directory, with no data loss, no correctness impact and no security effect; the retention is a deliberate, code-documented safety choice, and the test name explicitly records that it lasts "until a real descendant reaper exists". The residual defect is only that no bounded reclamation path exists. (2) "a repository-wide search for `cleanupPath` finds only the two writers" — there are three writers, `packages/tools/sandbox-appcontainer.ts:409` is missing; the conclusion is unaffected. (3) "accumulates that data without bound" is overstated: it is bounded by boot (macOS `os.tmpdir()` is the per-user `/var/folders/.../T` the system recreates at boot and reaps periodically), bounded by how many commands are run, and a per-command scratch is only populated if the command actually writes to `HOME`/`TMPDIR` — a `git status` leaves an essentially empty directory. (4) The proposed fix is riskier than presented: "sweep `yuantu-seatbelt-*` once at Host startup" is process-scoped, and this project runs desktop, Host and CLI against the same user profile concurrently (`README.md:735` has to tell operators to close all of them together; `windows-sandbox/README.md:9` handles a second Host for the same user), so a second Host's startup sweep can delete a live command's `HOME`/`TMPDIR` — exactly the race the retention rule exists to avoid; an age threshold alone does not fix that, an ownership marker does. (5) The alternative "drop the `cleanupPath` field from seatbelt plans" is a red herring for the leak: the directory is owned through the private `SeatbeltScratchRegistry` WeakMap, so removing the public field changes nothing about reclamation.

**Reasoning:** The cited lines say exactly what the finding claims, the early-return on `started` is the only cleanup path, and nothing anywhere in the product reads or sweeps these directories, so on the shipped macOS desktop a directory is created per command and kept for the life of the boot. But the behaviour is deliberate and documented in the code that implements it, with a stated safety reason (no descendant reaper on Darwin) rather than an oversight, and the cost is temp-directory disk growth that the OS reclaims rather than a functional or security failure; that combination puts it at low, not medium. The recommendation also needs an ownership marker rather than a bare startup age-sweep, because concurrent Hosts share the same temp root.
