## CAPABILITIES

1. One window, one Host at a time. `main.ts` keeps a single `BrowserWindow` (`apps/desktop/main.ts:53`, `apps/desktop/main.ts:660-682`) and one `CarrierService` per workspace (`createService`, `apps/desktop/main.ts:278-299`); a workspace switch starts the new service before stopping the old one and only the new one is attached (`apps/desktop/main.ts:1094-1120`). `attach()` forwards four carrier streams to the renderer as `yuantu:state`, `yuantu:delta`, `yuantu:subagent-delta`, `yuantu:statistics-delta` (`apps/desktop/main.ts:395-427`); `preload.ts:11-47` exposes exactly those four subscriptions plus `subscribePresets` (`yuantu:presets-view`) and nine invoke channels (`backups`, `readAttachment`, `files`, `mcp`, `presets`, `uiSettings`, `sandboxSetup`, `settings`, `invoke`) — no `ipcRenderer`, no `require`.
2. Window hardening: `nodeIntegration:false`, `contextIsolation:true`, `sandbox:true`, `webSecurity:true` (`apps/desktop/main.ts:668-675`); a CSP meta of `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-src 'none'` (`apps/desktop/index.html:6-9`); every `window.open` denied, navigation cancelled, and the session's permission-request and permission-check handlers both return false (`apps/desktop/main.ts:683-688`).
3. Every IPC handler begins with `assertSender`, which requires `event.sender === window.webContents`, `event.senderFrame === webContents.mainFrame`, and `event.senderFrame.url === pathToFileURL(pagePath).href` (`apps/desktop/main.ts:690-698`); each handler then runs its own parser (`parseCarrierCommand`, `parseBackupCommand`, `parseFilesCommand`, `parseMcpCommand`, `parsePermissionPresetCommand`, `parseSettingsCommand`, `parseUiSettingsCommand`, `parseSandboxSetupCommand`).
4. External links have one narrow path: `openLink` is accepted only for `http`/`https` with no credentials, at most 4096 characters and no character ≤ U+0020 (`packages/carrier/contract.ts:396-406`), and that is what reaches `shell.openExternal` (`apps/desktop/main.ts:1073-1074`); markdown links are validated by the same rule (`apps/desktop/markdown.ts:23-33`, `apps/desktop/markdown.ts:103-118`).
5. Model and tool text is drawn as text nodes: `renderMarkdown` creates every element with `textContent` (`apps/desktop/markdown.ts:38-42`), turns raw HTML tokens into text (`apps/desktop/markdown.ts:95-97`), renders images as the literal `[图片: alt]` instead of fetching them (`apps/desktop/markdown.ts:121-125`), and copies only TEXT/SPAN nodes out of highlight.js output parsed with `DOMParser` (`apps/desktop/markdown.ts:195-215`). Highlighting runs only for the eight registered languages and only when a code block is ≤30000 characters (`apps/desktop/markdown.ts:12-22`, `apps/desktop/markdown.ts:195`); markdown degrades to plain text above 120000 characters, above 12000 tokens, or at nesting depth > 32 (`apps/desktop/markdown.ts:46-50`, `apps/desktop/markdown.ts:58-64`).
6. Tool results are validated, not cast: `toolCardModel` accepts only three exact shapes (`file-read`, `search-results`, `command-output`) and returns `null` for anything else including a missing field on an older log (`apps/desktop/tool-card-model.ts:82-89`, `apps/desktop/tool-card-model.ts:170-288`), after which the caller draws the untouched text (`apps/desktop/tool-cards.ts:15-22`). A search card draws at most 100 rows (`MATCH_ROWS`, `apps/desktop/tool-cards.ts:30`), and the raw result text always stays one `<details>` deeper (`apps/desktop/tool-cards.ts:15-17`).
7. Sandbox and approval are one per-session choice: three presets — observe (native + read-only), guarded (native + ask, the default for a new session), unconfined (host + full-access) (`apps/desktop/permission-presets.ts:26-34`) — and `unconfined` is impossible without `acknowledgeHost: true`, which `parseSandboxSettingsCommand` enforces in the main process (`apps/desktop/sandbox-settings.ts:44-45`) and the preset parser routes through it (`apps/desktop/permission-presets.ts:93-97`). A pair matching no preset reads as `custom` and cannot be selected (`apps/desktop/permission-presets.ts:34`, `apps/desktop/permission-presets.ts:53-62`). The desktop keeps the pair per session id in memory (`apps/desktop/main.ts:440-447`) and re-applies it when the displayed session changes (`applyChoice`/`followSession`, `apps/desktop/main.ts:455-507`).
8. Attachments: `yuantu:attachment` is single-flight and spawns one `Worker` thread per read with `maxOldGenerationSizeMb: 256` and a hard 20 s timeout (`apps/desktop/main.ts:719-760`); the renderer accepts at most 8 files per message (`apps/desktop/renderer-attachments.ts:146`) and checks per-file sizes before sending (`apps/desktop/renderer-attachments.ts:165`, `apps/desktop/renderer-attachments.ts:179`). Extraction caps are 20 MB per document (`apps/desktop/attachment-contract.ts:7`), PDF ≤ 200 pages and ≤ 60000 characters of extracted text, XLSX ≤ 50 sheets and ≤ 1000 rows × 100 columns (`apps/desktop/attachment-reader.ts:28-65`).
9. Credentials: model keys are encrypted with Electron `safeStorage` and the store refuses to load or save when it is unavailable (`apps/desktop/model-settings.ts:95`, `apps/desktop/model-settings.ts:518`); the file is written `mode: 0o600` via a `wx` temp file plus `rename` (`apps/desktop/model-settings.ts:528-545`); the renderer never receives a key — `publicConnection` returns `hasKey: Boolean(apiKey)` (`apps/desktop/model-settings.ts:269`) — and at most 100 connections are accepted (`apps/desktop/model-settings.ts:100`).
10. Backups: the desktop creates or restores only on request; a restore id must match `^\d+-[a-f0-9-]{36}\.sqlite$` (`apps/desktop/backup-contract.ts:23-28`) and the work runs in a separate Node process with a 300 s timeout (`apps/desktop/main.ts:315-325`). The daily-schedule path still exists (`apps/desktop/daily-backups.ts:103-116`) but nothing in `main.ts` calls `configure`, `tick` or `load`, so the schedule is inert.
11. i18n: one zh/en dictionary in `apps/desktop/i18n.ts` is read by both processes — the main process through `mainText`/`setMainLocale` (`apps/desktop/i18n.ts:1061-1068`, set at `apps/desktop/main.ts:597` and `apps/desktop/main.ts:928`), the renderer through `t`/`format`. The renderer modules also carry Chinese source text that a document walker translates at render time from an exact-match reverse index of the dictionary (`apps/desktop/i18n.ts:1031-1032`) plus seven hard-coded regexes (`apps/desktop/i18n.ts:1077-1087`), driven by a `MutationObserver` on `document.body` (`apps/desktop/i18n.ts:1124-1131`); text under `script`, `style`, `pre` and `.message-content` is skipped, and `placeholder`/`aria-label`/`title` attributes are translated too (`apps/desktop/i18n.ts:1090-1117`).
12. The i18n static gate scans every `.ts` under `apps/desktop` for Han characters after stripping comments, with exactly four named exclusions, and fails when an exclusion matches no file (`scripts/i18n-gate.mjs:53-70`, `scripts/i18n-gate.mjs:156-202`). The renderer half of the gate is `tests/desktop.smoke.mjs`, which switches to `en-US` and asserts no visible Han in the general settings tab, the model settings tab and the chat page, skipping `#messages`, `.message-content` and `pre` (`tests/desktop.smoke.mjs:844-887`).
13. Renderer state: no framework; `render()` decides what to redraw by comparing string keys — transcript `${sessionId}:${messageRevision}:${locale}:${paused}` (`apps/desktop/renderer.ts:416-419`), changes and approvals by `JSON.stringify` (`apps/desktop/renderer.ts:431-436`, `apps/desktop/renderer.ts:497-499`) — while the transcript keeps per-index view objects and rebuilds only entries whose message differs under a recursive deep comparison (`apps/desktop/transcript-cache.ts:18-39`), reordering with `reconcileChildren` so untouched nodes keep focus, selection and open folds (`apps/desktop/transcript-cache.ts:42-53`).
14. Streaming and clocks: assistant deltas accumulate in a buffer and repaint on a coalesced 100 ms timer, and the buffer is dropped when the run stops or the live message id changes (`apps/desktop/renderer-live.ts:74-169`); answer and reasoning are separate buffers. A sub-agent clock runs a 1 Hz `setInterval` only while some child is running (`apps/desktop/renderer-subagents.ts:374-381`), and its `live` map is pruned to the ids the snapshot still carries (`apps/desktop/renderer-subagents.ts:653-661`). Background job cards update elapsed time per card without rebuilding rows (`apps/desktop/renderer-background.ts:73-142`).
15. Shutdown and upgrade: a single-instance lock rejects a second launch (`apps/desktop/main.ts:531-535`); `before-quit` refuses the first quit, waits for sandbox initialization, an in-flight restore, running backup workers and the daily-backup drain, stops both carrier services, then quits for real (`apps/desktop/main.ts:543-565`). Upgrade is manual and Windows-only, staged from a verified release by a separate Node worker (`timeout: 300000`, `maxBuffer: 1 MB`, last stdout line parsed as JSON, `apps/desktop/main.ts:139-146`), with a journal that must live under `<userData>/upgrades` and be named `upgrade.json` (`apps/desktop/main.ts:95-116`, `apps/desktop/main.ts:117-226`).
16. Packaged Windows builds install an application menu holding the upgrade entries plus `editMenu`/`viewMenu` roles (`apps/desktop/main.ts:598-627`) and then call `window.removeMenu()` on the window (`apps/desktop/main.ts:676`).

## FINDINGS

### desktop-app-1 | medium | correctness

**Title:** Person-facing copy lives outside the dictionary in both directions: most run states, two refusal paths and every exported session file stay Chinese in English mode, while the permission chip answers in English in Chinese mode

**Evidence:** The static gate exempts `renderer*.ts` because "its Chinese source text is the mechanism, and the DOM walker checks what a person ends up seeing" and exempts `attachment-contract.ts` as "instructions rather than something a person reads" (`scripts/i18n-gate.mjs:53-70`). The walker it trusts only substitutes an exact whole-text match: `domText` is built as Chinese→English from the dictionary's first elements (`apps/desktop/i18n.ts:1031-1032`) and `translatedText` does `domText.get(m[2]) ?? m[2]` plus seven fixed regexes (`apps/desktop/i18n.ts:1072-1089`). Against that:

- `apps/desktop/renderer.ts:386-403` writes `#run-status` (`apps/desktop/index.html:237-238`, a visible `role="status"` span) from a hardcoded map. Only `'准备就绪'` (`apps/desktop/i18n.ts:824`) and `'本轮已结束'` (`apps/desktop/i18n.ts:805`) are dictionary values; `'正在处理'`, `'已停止'`, `'验收未通过，需检查'`, `'已达到运行限制'`, `'运行失败'`, `'正在整理上下文…'`, `'等待你的确认'`, `'连接未就绪'` and `'正在加载会话…'` appear nowhere in `i18n.ts` (verified by searching the dictionary for each as an exact value). The same property is written correctly next door at `apps/desktop/renderer.ts:406-407` via `t('ui.modelReasoning')`/`t('ui.modelToolCall')`, and the approval panel's labels at `apps/desktop/renderer.ts:506-540` happen to be dictionary values — so the mechanism works only where the string was also entered into the dictionary.
- `apps/desktop/renderer-commands.ts:291-292` returns `` `/${name} 需要描述内容。` ``, while the dictionary stores the _unsubstituted template_ `'/{name} 需要描述内容。'` (`apps/desktop/i18n.ts:698`). An exact-match reverse index cannot match substituted text, so this entry can never fire; the string goes to the banner through `apps/desktop/renderer-composer.ts:54-59` → `apps/desktop/renderer.ts:313-328`.
- `apps/desktop/attachment-contract.ts:15-17` throws `'消息与附件内容合计超过 100000 字符，请减少附件或拆分发送。'`, put in the same banner by `apps/desktop/renderer-composer.ts:74-79` and re-wrapped with the file name by `apps/desktop/renderer-attachments.ts:188-191` (the wrapper alone makes an exact match impossible even for strings that are dictionary values, e.g. `'图片读取失败'` at `apps/desktop/renderer-attachments.ts:169`).
- `apps/desktop/renderer-commands.ts:142-153` builds the `/export` body from `'你'`/`'助手'`/`'工具'` and the title fallback `'新会话'` (the dictionary has `'新建会话'` at `apps/desktop/i18n.ts:361`). That text is written straight to disk by `apps/desktop/main.ts:1077-1091` and never enters the DOM, so no walker can ever translate it.
- The mirror case: `main.ts` is inside the gate (only Han characters are reported, so English copy is invisible to it) and holds person-facing messages in English — `'Wait for the current desktop operation before changing the sandbox.'` (`apps/desktop/main.ts:874-877`) becomes `reply.error` and is shown by `window.alert` (`apps/desktop/renderer-permissions.ts:74`); also `'Change the sandbox through a confirmed permission preset.'` (`apps/desktop/main.ts:1067`), `'Desktop is shutting down'` (`apps/desktop/main.ts:1068`), `'Workspace is changing'` (`apps/desktop/main.ts:1093`), `'Wait for the current operation to finish'` (`apps/desktop/main.ts:1097`) and the success text `Preset applied: …` (`apps/desktop/main.ts:900`).
- The renderer half of the gate samples exactly three moments: the general settings tab, the model settings tab and an idle chat page (`tests/desktop.smoke.mjs:868-887`), explicitly skipping `#messages,.message-content,pre` (`tests/desktop.smoke.mjs:856`). `#error` is empty and `#run-status` shows the one translated idle label at that moment, so no refused command, no in-flight run and no attachment failure is ever inspected.

**Impact:** In `en-US` the status line reads Chinese for every state except idle and the two model-phase labels; typing `/goal` or `/plan` with no argument, or attaching documents whose text exceeds 100000 characters, prints a Chinese sentence in an English window; and every exported session Markdown starts with `# 新会话` and Chinese `## 你` / `## 助手` / `## 工具` headings. In the default `zh-CN` interface the permission chip's own refusal is the opposite way round — an English sentence in a Chinese window. `npm run i18n:check` reports success for all of it, because the two Chinese files are excluded by name and English text in `main.ts` matches no Han character, so README:563/766 ("界面文案由 zh/en 双语字典驱动", "两个进程读同一本字典") is stronger than what the mechanism delivers.

**Recommendation:** Take these paths out of the walker's hands: read the run-status labels and the two refusal messages through `t()`/`mainText()` (adding the missing keys), make `exportConversation` emit localized role headings, and move the English literals in the `yuantu:presets`/`yuantu:command` handlers into `mainText`. If the walker is to stay, make the smoke switch to `en-US` during a run and after a refused command, and add an offline check that every Han literal in an exempted renderer module is either a dictionary value or reached through `t()` — and, for the main process, that every person-facing string is a `mainText` call rather than a bare literal.

**Confidence:** high

### desktop-app-2 | medium | correctness

**Title:** Changing the interface language without saving leaves the renderer in one language and the main process in the other; a restart silently reverts the choice

**Evidence:** The language select applies immediately on `change` — `apply(current())` on every control change (`apps/desktop/renderer-general-settings.ts:107-112`), and `apply` calls `setLocale`, which rewrites the whole document (`apps/desktop/i18n.ts:1119-1135`). The value is persisted only on form submit (`apps/desktop/renderer-general-settings.ts:114-145` → `apps/desktop/main.ts:910-934`), and the main process's own locale is set in exactly two places: startup (`apps/desktop/main.ts:597`) and after a successful save (`apps/desktop/main.ts:928`). Leaving the settings page does not undo a pending edit: `backToChat` clears the key field and re-reads the _connection_ list only (`apps/desktop/renderer-settings.ts:325-345`), and nothing re-fills the general form.

**Impact:** After selecting English and clicking back (or pressing Escape) without saving, the window is English while every string the main process composes is still Chinese: settings validation errors (`settings.apiKeyRequired`, `settings.apiKeyRequiredAfterChange` at `apps/desktop/model-settings.ts:312-315`, rendered verbatim by `apps/desktop/renderer-settings.ts:302-303`), the model-settings busy refusal (`mainText('settingsMain.busy')`, `apps/desktop/main.ts:966`, shown as the page's feedback), a failed sandbox initialization (`mainText('sandboxSetup.failed')`, `apps/desktop/main.ts:954`), and the export dialog's own title and filter labels (`mainText('desktop.exportTitle')`, `apps/desktop/main.ts:1079`). Because the file was never written, the next launch silently returns the whole interface to the persisted language, so the control appears not to have worked. README:766 makes the opposite claim about these two processes ("设置页的标签和它自己的报错不会各说一种语言").

**Recommendation:** Only apply the locale after the save reply (or restore `persisted` in `backToChat`), so the renderer's language and the main process's `mainLanguage` always move together.

**Confidence:** high

### desktop-app-3 | low | correctness

**Title:** The locale walker rewrites text the app does not own, so a workspace entry or session title that equals a UI string is displayed under a different name

**Evidence:** `translateDocument` walks every text node under `document.body` (and each subtree added later, via the `MutationObserver` at `apps/desktop/i18n.ts:1124-1131`), skipping only `script,style,pre,.message-content` (`apps/desktop/i18n.ts:1098`), and it also rewrites the `placeholder`, `aria-label` and `title` attributes of every element (`apps/desktop/i18n.ts:1106-1116`). Substitution is an unconditional exact-match lookup with no notion of data vs copy (`apps/desktop/i18n.ts:1072-1075`). The workspace tree draws entry names as plain text (`apps/desktop/renderer-workspace.ts:227`) and carries the real relative path in a `title` attribute (`apps/desktop/renderer-workspace.ts:230`); the session list draws titles (`apps/desktop/renderer-session-list.ts:61`) as does the chat header (`apps/desktop/renderer.ts:299-302`). The dictionary contains bare words that are ordinary names in a Chinese workspace: `'工具'` (`apps/desktop/i18n.ts:619`), `'任务'` (`apps/desktop/i18n.ts:615`, `apps/desktop/i18n.ts:757`), `'设置'` (`apps/desktop/i18n.ts:377`), `'技能'` (`apps/desktop/i18n.ts:448`), `'计划'` (`apps/desktop/i18n.ts:508`), `'取消'` (`apps/desktop/i18n.ts:441`), `'保存'` (`apps/desktop/i18n.ts:308`), `'删除'` (`apps/desktop/i18n.ts:709`), `'搜索'` (`apps/desktop/i18n.ts:764`).

**Impact:** In `en-US`, a directory named exactly `工具` is listed as `Tool`, a session whose title is exactly `任务` (titles are model-generated, so the app does not choose them) is listed as `Tasks`, and the tooltip that exists precisely to show the true path is rewritten the same way — the reader is shown a name that does not exist, with nothing in the window distinguishing it from a real one. The smoke cannot see it: its fixtures are ASCII, and `.message-content` is skipped anyway. Switching back to `zh-CN` restores the strings, because `translatedText` returns early (`apps/desktop/i18n.ts:1073`) and the original is kept in `originals`.

**Recommendation:** Stop running the walker over data-bearing surfaces: read those labels through `t()` at their call sites, and at minimum give data containers a skip attribute that `translateDocument` honours next to the existing `.message-content` check.

**Confidence:** medium
