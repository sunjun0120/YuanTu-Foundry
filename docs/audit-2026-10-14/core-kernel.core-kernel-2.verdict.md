**Reasoning:** The code really does this: `ResidentToolOptions` has no `usage` accumulator, `agent.ts:1507-1519` therefore cannot pass one, and `settle` folds follow-up spending into `statistics` only, while the delegation path folds every child turn it awaits into both accumulators (`subagents.ts:1159` → `run-coordinator.ts:99-113`). The failure mode is concrete but narrow — `RunResult.usage` (wire, `runs.result`, CLI `--json`) silently excludes the tokens of every `send_message` follow-up turn run during the run, while the session statistics and the desktop UI include them, and no field flags the gap. It is not a documented deliberate boundary and no test or runtime invariant covers it, so it stands as a real correctness/reporting inconsistency, just a low-severity one.
