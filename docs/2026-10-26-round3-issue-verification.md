# 第三轮桌面报告：问题核对与修复

核对来源：`2026-10-25-desktop-real-models-round3.md`。保留核对前已有的四类错误本地化改动。

## 执行顺序

1. 核对任务草稿标题、创建后面板发布时机；先用延迟模型响应复现，再修复。
2. 区分浏览器依赖缺失与启动失败，保留底层异常；用真实 Chromium 和 Electron 复测。
3. 核对 Windows 沙箱 SID 持久化及授权日志锁；修复确认的并发问题并改善诊断。使用临时状态目录测试，不操作真实沙箱账户。
4. 用受控端点覆盖目标自动第二轮及完成落盘，消除外部触发文件的时序竞争。
5. 复验已有本地化改动，运行仓库检查和构建，将证据与未覆盖项写回本文。

## 初步核对

- `/task` 的 `Goal:` 标题属实。任务已创建后，Carrier 要等待 `task.propose` 模型规划结束才发布，能解释报告的五秒不可见。
- 浏览器的两个 catch 确实把导入失败及任意启动失败都变成同一安装建议。正常 Windows 用户环境的源码和诊断 bundle 均可启动 Chromium，暂不能认定为打包故障。当前执行沙箱会改变 Playwright 默认缓存目录；显式指向已安装缓存后也能启动。
- 沙箱并非没有跨进程协调：原生授权日志已有文件锁，但等待上限为五秒。`cap-sids.json` 只有进程内写队列，跨进程修改可能覆盖其他映射，缓存也可能返回尚未成功持久化的 SID。历史 EPERM 是否由并发引发，报告证据不足以单独证明。
- 目标续跑探针在 `settle()` 返回后才写触发文件，而 Host 的同一次请求会直接执行后续轮次；这个探针无法可靠地在轮次之间触发条件。

SID 状态仍按 Windows 用户共享，与原生账户和授权日志的作用域一致；没有通过为每个 Host 随机生成身份或拆分原生授权日志来回避协调。旧版 Host 与新版 Host 同时运行的混合版本协作不属于本次保证。

直接运行真实 Electron 测试时，本机系统临时目录出现过访问失败；把 `TEMP`/`TMP` 指向仓库 `.scratch` 后通过。所有验收使用独立 profile 和工作区；未读取真实模型凭据。原生 Windows 账户的实际隔离验收仍需按现有约束在 CI 验证。
