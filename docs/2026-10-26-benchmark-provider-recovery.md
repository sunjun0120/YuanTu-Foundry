## DSML 调用链

- OpenAI Chat 的 DeepSeek 模型路由自动识别已观察到的完整 DSML 格式；其他别名需要 `deepseekCompatibility=on`，`off` 禁用兼容。
- 只接受正文末尾独立、未引用的调用块；支持碎片化 SSE、多个调用、原样多行字符串和非字符串 JSON 参数。代码围栏、缩进代码、行内示例和显式引用保留为正文。未加引用标记的完整尾部调用块按协议处理；展示语法示例时应使用代码围栏。
- 在返回任何调用之前，整批校验本轮可见工具名及参数 JSON Schema。不推断别名、不修正参数类型、不自动补必填项。未知工具、参数错误、残缺标签、重复参数、混合原生调用或已禁用工具均明确失败，保留已报告 usage；不执行半批调用。
- 正常文本继续流式显示，只缓冲潜在的协议后缀；中断时保留普通文本。截断或内容过滤响应不执行调用。解析通过后仍由现有 registry、审批、路径限制和沙箱决定能否执行。
- 调用 ID 和参数以标准 Chat 格式回放。原生推理保留继续遵守现有路由能力策略：第三方网关需显式兼容 opt-in，未擅自向自动模式的网关发送扩展字段。
- 校验器限定在单个解析批次内，避免进程缓存不断保留各轮新建的 schema 对象。

## 超时和未来基准配置

响应头等待现在报 `Model response headers timeout`；流空闲仍报 `Model stream idle timeout`，失败码保持 `timeout`。产品时限默认值及历史 manifest 缺省语义不变。已有零字节重试继续由 run 层统一负责，未增加第二套重试循环。

后续示例显式使用：响应头 120 秒、流空闲 60 秒、请求总时限 600 秒、输出 16384 token、一次零字节重试。示例仍未授权真实模型调用。重试有持久事件记录，只处理未收到响应体字节和已解析事件的连接失败；上游仍可能计费。这些设置参与配置身份，不能将新旧批次当作同条件实验。
